# モニター（UN-15TD8D）の探索挙動

最終更新: 2026-10-28

対象: チューナーが居ない状態のモニターが、5GHz 上で何をしているか。
読み取り専用（モニタ受信のみ、送信なし）。

## 方法

`rtl8812bu.monitor` で受信し、`tools/session_summary.py` で集計。

1. ch40 固定で 60 秒
2. ch36 / 40 / 44 / 48 を 15 秒ずつ巡回して 60 秒

## 結果 1: プローブ要求の形

モニターは **8.2 秒ごとに 2 通**（SSID 指定 + ワイルドカード）を送る。

| 項目 | 値 |
|---|---|
| 宛先 | ブロードキャスト |
| SSID 指定プローブ | 対象 SSID（非公開） / 長さ 194 |
| ワイルドカード | SSID 空 / 長さ 175 |
| Supported Rates | 12,18,24,36,48,72,96,108（= 6〜54 Mbps、**OFDM のみ**＝CCK 無し → 5GHz 専用の振る舞い） |
| HT Capabilities (45) | 26 バイト |
| RSN (48) | 無し（プローブでは通常） |
| **WPS (221)** | **`00:50:f2:04`、105 バイト** |

### WPS IE の中身

| 属性 | 値 | 意味 |
|---|---|---|
| Version (0x104a) | 0x10 | WPS 1.0 |
| **Request Type (0x103a)** | **0x00** | **Enrollee（登録したい側）** |
| Config Methods (0x1008) | 0x2288 | Display / PushButton / VirtualPushButton / PhysicalPushButton / VirtualDisplayPIN |

つまりモニターは **「WPS の登録者（Enrollee）」として、レジストラ（親機）を探している**。
PBC（ボタン）と表示 PIN の両方を申告している。

## 結果 2: チャネルの動き（訂正）

**モニターは 36/40/44/48 の 4 チャネルを約 8.2 秒で 1 周し、各チャネルを訪れるたびに
プローブ要求を 1 組（SSID 指定 + ワイルドカード）送る。** 1 チャネルあたりの滞在は約 2 秒。

根拠（3 通りの測り方で一致）:

| 測り方 | 結果 |
|---|---|
| ch40 に固定して 300 秒 | 36 組が **8.2 秒間隔**（欠けなし） |
| ch36 に固定して 180 秒 | 21 組が **8.2 秒間隔** |
| 36/40/44/48 を 15 秒ずつ巡回 | 各ウィンドウに約 2 組（15 ÷ 8.2 ≒ 1.8） |

固定受信で 8.2 秒ごとに届く＝モニターは 8.2 秒ごとにそのチャネルへ戻ってくる、
という読み。したがって**相手が 36/40/44/48 のどれかに居れば、約 8 秒以内に
プローブが届く**（発見まで 1 分かかる、という当初の見積りは誤り）。

### 補足（未確定）

- 5 分観測の 223 秒付近で 1 回だけ 4.0 秒間隔の変則があった（訪問の飛び）。
- 巡回の周期が負荷や状態で変わるかは未確認。

## 結果 3: 2.4GHz でも探索している（訂正）

**モニターは 2.4GHz（ch1 / ch6 / ch11）でも 5GHz（ch40）でも同じ SSID を指定して
プローブする。** 以前「5GHz のみ」と書いたが、それはモニターが停止／待機していた
時間帯に測ったための誤り（そのときはモニターのフレームが 0 件だった）。

### 追試（モニター電源 ON・各チャネル 30 秒）

| チャネル | プローブ数 | バースト間隔 |
|---|---:|---|
| ch1 | 21 | 8.0 / 8.0 / 8.1 秒 |
| ch6 | 25 | 7.9 / 7.8 / 7.8 秒 |
| ch11 | 25 | 7.8 / 7.8 / 7.8 秒 |
| ch40 | 4 | 8.2 秒 |

- どのチャネルでも **約 8 秒ごとに「SSID 指定＋ワイルドカード」のペアを数組**送る。
- 2.4GHz の方が 1 回あたりの組数が多い（ch11 で 5〜6 組）＝2.4GHz を優先的に探っている。
- ビーコンは 1,232 件受信しており、受信系は健全（IE チャネル一致 1,231/1,232）。

### 以前の観測（参考・誤りを含む）

2.4GHz を含む短い巡回でモニターのフレームが 0 件だったため「5GHz のみ」と判断したが、
その時間帯はモニターが電波を出していなかった（後日の追試で 0 件を再現）。
測定は「相手が動いていること」を確認しながら行う必要がある。

## モニターだけのセットアップに必要なこと（含意）

1. **チャネル**: 2.4GHz（1/6/11）でも 5GHz（36/40/44/48）でもよい。
   モニターは約 8 秒ごとに各チャネルへプローブを出すので発見は速い。
   2.4GHz の方が本数が多く、到達距離でも有利。
2. **SSID / バンド**: モニターは対象 SSID を 2.4GHz・5GHz の両方で探している。
   同じ SSID でビーコン／プローブ応答を返せば見つけてもらえる。
   **プローブは約 8 秒ごとに届く**（2.4GHz の方が本数が多い）。
3. **WPS**: モニターは Enrollee として WPS を要求している。応答側は
   **レジストラ**として WPS（EAP-WSC の M1〜M8）を話す必要がある。
   モニターは PBC を申告しているので、ボタン方式で進められる可能性が高い。
4. **鍵**: WPS で渡す資格情報（SSID/PSK）で、その後の 4-way が成立する必要がある。
